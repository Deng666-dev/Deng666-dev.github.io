前言

本文记录了 DVWA 靶场所有漏洞的攻击记录，因为感觉每攻破一道题特别的爽，所以都特别详细的记录下来

Brute Force

工具：bp 浏览器：chorm

Brute Force（Low）

最低的级别，web应用对用户的输入和认证频率几乎是不设防的，一点难度没有有脚就行

  • 防御措施：为0
  • 判断依据：在网页中多次输入账号和密码时，并没有进行锁定，HTTP 响应无变化
  • 详细步骤见这一篇文章:DVWA LOW难度详细步骤
  • 攻击思路：由于没有任何放爆破机制，攻击者随便使用自动化工具，通过字典枚举密码，来看返回包中的长度差异或状态码判断是否破出账密

Brute Force（Medium）

难度为中，上升了一点点，搞心态，延缓攻击者的脚本

  • 防御措施：为1.5 引入了sleep(2)函数，导致每次登录失败的时候，服务器会强制等待2秒钟再返回结果，同时使用了mysql_real_escape_string防止简单的 SQL 注入，如 sleep设置为100或1000，加大 SQL注入的风险，爆破破个几小时都出不来账密
  • 判断依据：进行攻击的时候，明显可以感觉到破解速度极慢，每次只反应几个包，发包和接收响应时间特别的慢，错误密码的请求耗时会明显增加
  • 有耐心的可以慢慢等吧，慢慢爆破吧!

详细步骤：
浏览器打开bp代理，bp开启监听可以看见成功抓取到数据包，把账号和密码发送到 Intruder 进行攻击

攻击模式设置成 Cluster bomb attack 集束炸弹攻击

将账号密码添加到payload位置，这里我导入了密码本，可以依次输入账密或导入密码本，其中需有一个随机猜测为正常的账密，右侧 payload 下拉列表需要指定切换一下

开始进行攻击 可以看见响应特别的慢，延迟攻击

长度降序排序，可以看见长度明显与其他的不一样，成功抓取到账号和密码，返回到 DVWA 成功登录

Brute Force（High）

payload 提取

这里使用的是 payload 提取 Token 法，让 BP 在发送当前密码之前，先从上一次服务器的响应页面中把新的 token 拉出来，填到下一个请求包发出

  • 防御措施：引入了 Anti-CSRF Token[放跨站请求伪造令牌]，前几个难度是只要输入账号和密码就能进，现在相当于服务器每次都会给你一个随机的验证码，也就是 token，把它藏在网页表单里，并同时记录在服务器的 Session 中。如果进去登录提交时，服务器检测到提交的 token 是否一致，一旦验证过。旧token 就会作废
  • 判断依据：抓包时会出现一个动态变化的随机字符串user_token

详细步骤：

一样的操作打开代理返回 bp 开启监听，这里我们可以看见抓到的数据包多了一个动态的参数 token，我们需要固定参数 username，破密码和token，发送到 Intruder 进行攻击

配置提取规则：找到 Settings 选项卡—— Grep 提取模块—— 获取响应，可以看见表单的源码，可以直接搜索，我们只需要拿到 value 后面值，只需要选中 token 值，bp 会自动生成正则并匹配

但是在 bp 中会有鼠标选中的 bug，特别的恶心，鼠标选中都会有偏移，可以直接在上方进行填入对应的信息，就会把 token 高亮匹配出来

在当前页面中需要找到重定向选项卡设置成 ‘总是’，因为当爆破时密码错误，网页 302 会重定向页面，刷新后才会有新 token，如果不选择，就不会进行刷新 token，相当于就是一个死界面，同一个界面

返回 payload 列表添加密码本，其中需有一个猜测的正确的密码

设置 token 的payload 时需要为递归提取，设置完后当前的初始值会自动填充第一个请求包里抓取到的 token

设置一下单线程运行，因为我们需要上一个请求的返回结果来提供下一个请求的 token，最大并发数需要设置成1

以上步骤完成后就可以开始进行攻击，攻击方式需要选择 Pitchfork，成功后可以看见成功抓到 password 和 token

Macro 提取

递归提取虽然可以用，但是必须执行单线程，速度太慢，宏提取就是最强大的手段，它会让 bp 在后台当一个隐形人，每次发送密码前会去悄悄请求一次网页，获取最新的 token，放入爆破请求中

token 的作用：token为 Anti-CSRF Token,在放爆破的场景下，核心作用是破坏自动化和强制串行，与多线程并发有很大的区别，必须先跟服务器打招呼获取 token，后再进行提交，所以必须为单线程，如遇到大量密码本时会极大拖慢爆破进度

详细步骤：录制宏，抓取新的 token，在全局设置中寻找 Session 选项卡并添加宏

添加第一条状态码

配置会话处理规则，添加一条新规则

随便取个名字，再 Rule actions 中，需要添加 运行宏，添加后会跳出操作配置

需要选中刚刚添加的宏，勾选下方的 Update only the following 并手动添加 user_tokens即可

在上方的范围选项卡中，工具范围只能勾选 Intruder ，URL范围为包含所有



以上配置完后最后在恢复一下多线程就可以进行攻击，并发数可以设置成10或5，感受一下几秒爆破的感觉，需要注意的是：攻击模式需切换为 Sniper 狙击手模式，payload 只需要给密码添加，给 payload 导入密码本，不需要给 token 添加，因为录制的宏会自动在后台替换 token，随后开始攻击

最后成功抓取到密码！！！

宏提取 和 payload 提取只是手法不同，其他的防御机制基本一致。宏提取是利用代理工具的高级会话管理与自动化宏（Macros）功能，配置宏规则，使其在后台作为“隐形代理”，在每次发起真实爆破请求前，自动拦截并前置发送一次 GET 请求刷新登录页面，抓取最新 Token 并静默替换进爆破数据包中。这种降维打击使得前台的 Intruder 可以完全无视后端的动态防御机制，直接使用最简单的单变量字典（Sniper模式）进行高效并发爆破
