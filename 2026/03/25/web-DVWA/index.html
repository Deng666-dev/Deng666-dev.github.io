前言

本文记录了 DVWA 靶场所有漏洞的攻击记录，因为感觉每攻破一道题特别的爽，所以都特别详细的记录下来

Brute Force

工具：bp 浏览器：chorm

Brute Force（Low）

最低的级别，web应用对用户的输入和认证频率几乎是不设防的，一点难度没有有脚就行

  • 防御措施：为0
  • 判断依据：在网页中多次输入账号和密码时，并没有进行锁定，HTTP 响应无变化
  • 详细步骤见这一篇文章:DVWA LOW难度详细步骤
  • 攻击思路：由于没有任何放爆破机制，攻击者随便使用自动化工具，通过字典枚举密码，来看返回包中的长度差异或状态码判断是否破出账密

Brute Force（Medium）

难度为中，上升了一点点，搞心态，延缓攻击者的脚本

  • 防御措施：为1.5 引入了sleep(2)函数，导致每次登录失败的时候，服务器会强制等待2秒钟再返回结果，同时使用了mysql_real_escape_string防止简单的 SQL 注入，如 sleep设置为100或1000，加大 SQL注入的风险，爆破破个几小时都出不来账密
  • 攻击思路：进行攻击的时候，明显可以感觉到破解速度极慢，每次只反应几个包，有耐心的可以慢慢等吧，慢慢爆破吧!

详细步骤：
浏览器打开bp代理，bp开启监听可以看见成功抓取到数据包，把账号和密码发送到 Intruder 进行攻击

攻击模式设置成 Cluster bomb attack 集束炸弹攻击

将账号密码添加到payload位置，这里我导入了密码本，可以依次输入账密或导入密码本，其中需有一个随机猜测为正常的账密，右侧 payload 下拉列表需要指定切换一下

开始进行攻击 可以看见特别的慢，延迟攻击

长度降序排序，可以看见长度明显与其他的不一样，成功抓取到账号和密码，返回到 DVWA 成功抓取账号密码
